Narración:

¿Qué tal? Bienvenidos a Z2H Academy.

En este video quiero presentarles Tutor: qué es, por qué lo estamos construyendo y, sobre todo, qué problema queremos resolver.

Pero antes, un poco de contexto.

La forma en que aprendemos y construimos software está cambiando.

Durante años aprendimos con clases, videos, tutoriales, documentación, notebooks y ejercicios. Aprendíamos una tecnología, seguíamos algunos ejemplos y después intentábamos llevar ese conocimiento a un entorno real de trabajo.

Hoy estamos en otra etapa.

En la industria es cada vez más común trabajar con coding agents. Herramientas como Claude Code, Codex y OpenCode pueden analizar proyectos, entender su estructura, consultar documentación, modificar archivos, ejecutar comandos y participar directamente en el desarrollo.

El desarrollador ya no escribe cada línea manualmente. Trabaja junto a agentes capaces de construir.

Y eso nos lleva a una pregunta:

Si esta es la forma en que cada vez más profesionales construyen software, ¿por qué deberíamos seguir aprendiendo como si estos agentes no existieran?

En Z2H Academy decidimos aprovechar este cambio. No queremos enseñar a usar inteligencia artificial. Queremos una experiencia de aprendizaje que use las mismas herramientas y dinámicas del trabajo real.

Porque aprender una tecnología no es solo conocer su teoría. Es investigar, leer documentación, construir, ejecutar, depurar y validar.

Ahí aparece Tutor.

Tutor es el Agentic Learning Runtime de Z2H Academy. Conecta los coding agents con Roadmaps, Developer Docs, Labs, Projects y mecanismos de validación.

No es otro chatbot. Es el entorno donde el agente puede operar dentro de un proceso de aprendizaje.

En este video vamos a ver cómo funciona, cuál es su arquitectura, cómo se integra con distintos agentes y qué estamos construyendo.

Si el futuro del desarrollo es agéntico, el aprendizaje también tiene que serlo.

S06 · El flujo
En pantalla: De responder preguntas a ejecutar procesos_ · objetivo → roadmap → section → lab → validación

Narración:

Un chatbot está diseñado principalmente para responder preguntas.

Un Learning Runtime está diseñado para acompañar y ejecutar un proceso.

El flujo empieza con un objetivo de aprendizaje. Después, el agente navega el roadmap, identifica el level correspondiente, accede a una section y trabaja sobre un lab.

Viene la ejecución: el estudiante y el agente construyen, ejecutan comandos, investigan errores y corrigen problemas.

Y finalmente la validación: el resultado se comprueba y, cuando corresponde, se avanza.

Esto es importante porque no queremos que el aprendizaje termine cuando el agente genera una respuesta aparentemente correcta.

Queremos una conexión entre lo que se estudia, lo que se construye y lo que realmente funciona.

La diferencia está en pasar de generar respuestas a ejecutar procesos de aprendizaje.

S10 · MCP
En pantalla: Un protocolo como frontera_ · agents → MCP → Tutor → Z2H

Narración:

Una pieza importante de esta arquitectura es MCP, el Model Context Protocol.

MCP proporciona una interfaz estandarizada para que los coding agents puedan interactuar con herramientas y recursos externos.

En nuestro caso, permite conectar los agentes con las capacidades de Tutor.

Esto evita tener que construir una integración completamente diferente para cada coding agent.

En lugar de acoplar Tutor a una herramienta específica, utilizamos una interfaz que pueden implementar diferentes agentes compatibles.

Así podemos trabajar con Claude Code, Codex, OpenCode y otras herramientas que soporten esta integración.

Y lo más importante: Tutor puede evolucionar independientemente de cada agente.

Hay algo que conviene entender:

MCP no es Tutor ni es el producto. Es una de las piezas tecnológicas que permite conectar el runtime con los agentes.

S12 · Ejecución
En pantalla: El conocimiento permanece. La infraestructura cambia_ · 5 entornos

Narración:

Otro aspecto fundamental es dónde ocurre la ejecución.

El aprendizaje no debería depender de una infraestructura específica.

Un estudiante puede trabajar directamente en su máquina utilizando Linux, Docker o una máquina virtual.

También puede utilizar entornos remotos como GitHub Codespaces o servidores en la nube.

Y en disciplinas que requieren mayores recursos computacionales, podemos trabajar con infraestructura especializada y GPUs.

Esto es especialmente relevante en Data Engineering, Machine Learning e inteligencia artificial, donde determinados proyectos pueden necesitar recursos que no están disponibles en una máquina personal.

La idea es separar el proceso de aprendizaje del lugar donde se ejecuta el cómputo.

El mismo roadmap y el mismo lab pueden trabajarse desde diferentes entornos.

El conocimiento permanece. La infraestructura puede cambiar.

S13 · Aprender es ejecutar
En pantalla: Read. Build. Understand. Validate. Repeat._ · 5 verbos + loop

Narración:

Si tuviera que resumir nuestra filosofía de aprendizaje en cinco palabras, serían estas:

Read. Build. Understand. Validate. Repeat.

Leer documentación es importante, pero no es suficiente. Copiar código tampoco.

Necesitamos comprender cómo funciona un sistema, construirlo, ejecutarlo, investigar los problemas que aparecen, corregirlos y comprobar que el resultado funciona.

Y aquí los coding agents tienen un papel fundamental. Pueden ayudarnos a interpretar documentación, explorar alternativas, construir componentes, ejecutar comandos y depurar errores.

Pero hay algo que no debemos perder de vista:

Generar código no significa necesariamente haber construido algo que funciona.

Por eso la ejecución y la validación son fundamentales.

En Z2H queremos que el estudiante desarrolle la capacidad de trabajar con sistemas reales, utilizando agentes como parte de su proceso de ingeniería.

No se trata solamente de aprender tecnologías. Se trata de aprender a construir con ellas.
