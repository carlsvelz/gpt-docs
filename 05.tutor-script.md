# TUTOR — AGENTIC LEARNING RUNTIME
## Guion oficial del video de presentación de Z2H Academy

# INTRO — Bienvenida

Hola, ¿qué tal? Bienvenidos a Z2H Academy.

En este video quiero presentarles Tutor: qué es, por qué lo estamos construyendo y, sobre todo, qué problema queremos resolver.

Pero antes, quiero ponerlos en contexto.

**La forma en que aprendemos y construimos software está cambiando.**

Durante años, nuestra manera de aprender programación estuvo basada principalmente en clases, videos, tutoriales, documentación, notebooks y ejercicios.

Aprendíamos una tecnología, seguíamos algunos ejemplos y, después, intentábamos llevar ese conocimiento a un entorno real de trabajo.

Pero hoy estamos entrando en una etapa diferente.

En la industria cada vez es más común trabajar con coding agents.

Herramientas como Claude Code, Codex y OpenCode pueden analizar proyectos, comprender su estructura, consultar documentación, modificar archivos, ejecutar comandos, escribir código, investigar errores y participar directamente en el proceso de desarrollo.

Esto cambia radicalmente la dinámica de trabajo.

El desarrollador ya no necesariamente tiene que escribir cada línea de código manualmente. Ahora puede trabajar junto a agentes capaces de ejecutar tareas complejas y construir software.

Y esto nos lleva a una pregunta:

**Si esta es la forma en que cada vez más profesionales están construyendo software, ¿por qué deberíamos seguir aprendiendo como si estos agentes no existieran?**

En Z2H Academy decidimos aprovechar este cambio.

No queremos simplemente enseñar a utilizar herramientas de inteligencia artificial.

Queremos construir una experiencia de aprendizaje que incorpore las mismas herramientas y dinámicas que los profesionales están comenzando a utilizar en su trabajo diario.

Porque aprender una tecnología no debería limitarse a conocer su teoría o seguir un tutorial.

También implica aprender a investigar, leer documentación, construir sistemas, ejecutar código, depurar problemas y validar resultados.

Y aquí es donde aparece Tutor.

Tutor es el **Agentic Learning Runtime de Z2H Academy**.

Su propósito es conectar los coding agents con un sistema de aprendizaje estructurado que incluye Roadmaps, Developer Docs, Labs, Projects y mecanismos de validación.

La idea no es crear otro chatbot al que simplemente le hacemos preguntas.

Queremos que un coding agent pueda trabajar dentro de un entorno de aprendizaje, comprender qué está estudiando el estudiante, acceder al conocimiento correspondiente, ejecutar actividades prácticas y comprobar sus resultados.

En otras palabras:

**Queremos conectar la inteligencia de los coding agents con una experiencia de aprendizaje diseñada para construir conocimiento mientras construimos software.**

En este video vamos a explorar cómo funciona Tutor, cuál es su arquitectura, cómo se integra con los diferentes coding agents y qué estamos construyendo alrededor de esta tecnología.

Porque si el futuro del desarrollo es cada vez más agéntico, el aprendizaje también tiene que evolucionar.

Bienvenidos a Tutor.

**Let's build.**

# SLIDE 01 — Tutor conecta agentes con aprendizaje real

En Z2H Academy partimos de una idea: aprender construyendo, utilizando las mismas herramientas que están transformando el desarrollo de software.

Pero hay un problema.

Un coding agent, por poderoso que sea, no constituye por sí solo un sistema de aprendizaje.

Puede generar código, explicar conceptos y resolver problemas, pero necesita contexto para saber qué debe aprender el estudiante, qué conocimientos debe adquirir, qué proyecto debe construir y cómo comprobar si realmente lo ha conseguido.

Necesita una estructura que le dé dirección.

Y esa estructura ya existe en Z2H Academy.

Tutor es la pieza que conecta los coding agents con todo este ecosistema.

No reemplaza al agente ni intenta convertirse en otro chatbot.

Su responsabilidad es proporcionar la interfaz y el contexto necesarios para que el agente pueda operar dentro de un proceso de aprendizaje estructurado.

---

# SLIDE 02 — Del chatbot al entorno de aprendizaje

Para entender la diferencia, comparemos dos modelos.

En el modelo tradicional, una persona hace una pregunta, un chatbot genera una respuesta y, eventualmente, el estudiante copia algún código y trata de ejecutarlo por su cuenta.

El problema es que normalmente falta continuidad, estructura y validación.

En Z2H proponemos algo diferente.

Tenemos un sistema de aprendizaje organizado en Roadmaps, Levels, Sections, Developer Docs, Projects y Labs.

Tutor conecta toda esta estructura con los coding agents.

Y, por supuesto, tenemos el entorno donde ocurre el trabajo: la máquina del estudiante, Docker, una máquina virtual, GitHub Codespaces o infraestructura remota con GPU.

Cada componente cumple una función específica.

El agente aporta la capacidad de razonar y construir.

Z2H proporciona el conocimiento y la estructura de aprendizaje.

El entorno proporciona los recursos de ejecución.

Y Tutor conecta todos estos elementos dentro de un mismo proceso.

**Pasamos de utilizar IA para obtener respuestas a utilizar agentes para desarrollar un proceso de aprendizaje completo.**

---

# SLIDE 03 — Qué es Tutor: un Agentic Learning Runtime

Entonces, ¿qué significa realmente que Tutor sea un Agentic Learning Runtime?

Significa que proporciona al coding agent una interfaz estructurada para interactuar con el sistema de aprendizaje de Z2H Academy.

Por ejemplo, en lugar de preguntarle al agente cómo aprender Data Engineering y recibir una respuesta genérica, podemos trabajar directamente sobre un Roadmap.

El agente puede descubrir los Roadmaps disponibles, identificar el Level en el que estamos trabajando, acceder a una Section, consultar los Developer Docs y trabajar sobre un Lab específico.

También puede ejecutar código, interactuar con el entorno y utilizar mecanismos de validación.

Esto cambia completamente el contexto de trabajo.

El agente ya no está improvisando una ruta de aprendizaje a partir de información dispersa.

Está operando sobre una estructura que define qué aprender, qué construir y cómo avanzar.

**Tutor convierte el conocimiento de Z2H en un entorno operativo para los coding agents.**

---

# SLIDE 04 — Tutor no es el coding agent

Hay algo que quiero dejar muy claro: Tutor no pretende convertirse en otro coding agent.

Claude Code, Codex y OpenCode son los agentes.

Ellos aportan la capacidad de razonamiento, utilizan modelos de lenguaje, generan código, modifican archivos, ejecutan comandos y resuelven problemas.

Tutor tiene una responsabilidad diferente.

Proporciona el contexto, las herramientas y la interfaz necesarias para que esos agentes puedan trabajar dentro del ecosistema de Z2H Academy.

Esta separación es fundamental porque nos permite mantener una arquitectura independiente del agente.

Hoy podemos utilizar Claude Code.

También podemos trabajar con Codex u OpenCode.

Y mañana podemos incorporar nuevos agentes.

No necesitamos reconstruir el sistema de aprendizaje cada vez que aparece una herramienta nueva.

**El agente puede cambiar. La inteligencia puede evolucionar. Tutor permanece como la capa de integración con Z2H.**

# SLIDE 05 — Tutor no es la fuente de verdad

Otra distinción importante es dónde vive realmente el conocimiento.

Tutor no pretende convertirse en una gigantesca base de conocimiento ni duplicar toda la documentación de la academia.

La fuente de verdad está en los Developer Docs de Z2H.

Ahí se encuentran los conceptos, las explicaciones, las guías técnicas, los ejemplos, las instrucciones, las Sections y los Labs.

Los Roadmaps organizan ese conocimiento y definen la progresión del aprendizaje.

Tutor proporciona la interfaz para que los coding agents puedan descubrir, consultar y utilizar ese conocimiento.

La separación es deliberada:

El conocimiento vive en Developer Docs.

La estructura del aprendizaje vive en los Roadmaps.

La práctica ocurre en los Labs y Projects.

La inteligencia está en el coding agent.

Y Tutor conecta todas estas piezas.

**No queremos duplicar el conocimiento. Queremos hacerlo accesible y operativo para los agentes.**

---

# SLIDE 06 — De chatbot a Learning Runtime

Aquí está uno de los cambios conceptuales más importantes de Tutor.

Un chatbot está diseñado principalmente para responder preguntas.

Un Learning Runtime está diseñado para acompañar y ejecutar un proceso.

El flujo comienza con un objetivo de aprendizaje.

A partir de ahí, el agente puede navegar por el Roadmap, identificar el Level correspondiente, acceder a una Section y trabajar sobre un Lab.

Después viene la ejecución.

El estudiante y el agente construyen, ejecutan comandos, investigan errores y corrigen problemas.

Finalmente, entra en juego la validación.

El resultado se comprueba y, cuando corresponde, el estudiante puede continuar con el siguiente paso.

Esto es importante porque no queremos que el aprendizaje termine cuando el agente genera una respuesta aparentemente correcta.

Queremos que exista una conexión entre lo que se estudia, lo que se construye y lo que realmente funciona.

**La diferencia está en pasar de generar respuestas a ejecutar procesos de aprendizaje.**

# SLIDE 07 — Responsabilidades de Tutor

Ahora bien, ¿qué hace Tutor en la práctica?

Tutor permite descubrir los Roadmaps disponibles, navegar por Levels y Sections y acceder a los Developer Docs con el contexto adecuado.

También permite trabajar con Labs y Projects, interactuar con entornos locales y remotos, ejecutar workflows, investigar problemas y conectar las actividades con mecanismos de validación.

Para conseguirlo, utilizamos diferentes componentes tecnológicos.

Entre ellos encontramos MCP, herramientas, skills y los distintos mecanismos que forman parte del runtime.

Pero lo importante no es enumerar funcionalidades.

Lo importante es entender para qué existen.

Cada capacidad está diseñada para que el coding agent pueda interactuar con el sistema de aprendizaje y ejecutar tareas dentro de un contexto definido.

**Tutor no agrega herramientas por agregar. Cada herramienta tiene un propósito dentro del proceso de aprendizaje.**

# SLIDE 08 — Arquitectura general

Veamos ahora cómo está organizada la arquitectura.

Podemos entenderla a través de cuatro grandes componentes.

En la parte superior tenemos Z2H Academy.

Aquí viven los Roadmaps, Developer Docs, Labs, Projects y los mecanismos de validación.

En el siguiente nivel encontramos Tutor, que funciona como Agentic Learning Runtime.

Y finalmente está el entorno de ejecución del estudiante.

Puede ser Linux, Docker, una máquina virtual, GitHub Codespaces o incluso infraestructura remota con GPU.

Esta separación nos permite mantener independientes el conocimiento, la inteligencia y el cómputo.

Z2H proporciona el contenido y la estructura.

El coding agent aporta la capacidad de razonamiento y ejecución.

El entorno proporciona los recursos necesarios.

Y Tutor conecta todos estos componentes.

# SLIDE 09 — Separación de responsabilidades

La arquitectura funciona porque cada componente tiene una responsabilidad claramente definida.

El coding agent razona, interpreta instrucciones y construye.

Tutor proporciona el contexto y la interfaz para interactuar con Z2H.

Los Developer Docs proporcionan el conocimiento técnico.

Los Labs y Projects proporcionan los escenarios de práctica.

Y el entorno del estudiante proporciona el cómputo real.

Esto significa que podemos trabajar con bases de datos, contenedores, sistemas Linux, servicios cloud, GPUs y herramientas de desarrollo.

No necesitamos que una sola pieza se encargue de todo.

Tampoco necesitamos que el coding agent tenga que inventar una estructura de aprendizaje cada vez que comienza una tarea.

Cada componente se concentra en aquello para lo que fue diseñado.

**Esa separación es precisamente lo que hace que Tutor pueda evolucionar como infraestructura independiente.**

# SLIDE 10 — Por qué MCP

Una pieza importante de esta arquitectura es MCP, Model Context Protocol.

MCP proporciona una interfaz estandarizada para que los coding agents puedan interactuar con herramientas y recursos externos.

En nuestro caso, permite conectar los agentes con las capacidades de Tutor.

Esto evita tener que construir una integración completamente diferente para cada coding agent.

En lugar de acoplar Tutor a una herramienta específica, utilizamos una interfaz que pueden implementar diferentes agentes compatibles.

Así podemos trabajar con Claude Code, Codex, OpenCode y otras herramientas que soporten esta integración.

Y lo más importante: Tutor puede evolucionar independientemente de cada agente.

Hay algo que debemos entender:

**MCP no es Tutor ni es el producto. Es una de las piezas tecnológicas que permite conectar el runtime con los agentes.**

# SLIDE 11 — Diseño agnóstico al agente

Esta arquitectura nos permite mantener a Tutor agnóstico al coding agent.

Hoy podemos utilizar Claude Code, Codex u OpenCode.

Pero no queremos que el sistema de aprendizaje dependa de una empresa, un modelo o una herramienta específica.

La tecnología de los agentes está evolucionando constantemente.

Aparecen nuevos modelos, nuevas interfaces, nuevas capacidades y nuevas formas de ejecutar tareas.

Por eso queremos que Z2H pueda aprovechar esa evolución sin tener que reconstruir su infraestructura de aprendizaje.

El flujo fundamental permanece:

Coding Agent.

Tutor.

Z2H Academy.

Podemos cambiar el agente, incorporar nuevas capacidades o utilizar diferentes modelos.

Pero los Roadmaps, los Developer Docs, los Labs y la estructura de aprendizaje siguen siendo los mismos.

**No estamos construyendo una academia alrededor de un agente. Estamos construyendo una infraestructura que puede trabajar con diferentes agentes.**

# SLIDE 12 — Ejecución local y remota

Otro aspecto fundamental es dónde ocurre la ejecución.

El aprendizaje no debería depender de una infraestructura específica.

Un estudiante puede trabajar directamente en su máquina utilizando Linux, Docker o una máquina virtual.

También puede utilizar entornos remotos como GitHub Codespaces o servidores en la nube.

Y en disciplinas que requieren mayores recursos computacionales, podemos trabajar con infraestructura especializada y GPUs.

Esto es especialmente relevante en Data Engineering, Machine Learning e inteligencia artificial, donde determinados proyectos pueden necesitar recursos que no están disponibles en una máquina personal.

La idea es separar el proceso de aprendizaje del lugar donde se ejecuta el cómputo.

El mismo Roadmap y el mismo Lab pueden trabajarse desde diferentes entornos.

**El conocimiento permanece. La infraestructura puede cambiar.**

# SLIDE 13 — Aprender es ejecutar

Si tuviera que resumir nuestra filosofía de aprendizaje en cinco palabras, serían estas:

Read.

Build.

Understand.

Validate.

Repeat.

Leer documentación es importante, pero no es suficiente.

Copiar código tampoco.

Necesitamos comprender cómo funciona un sistema, construirlo, ejecutarlo, investigar los problemas que aparecen, corregirlos y comprobar que el resultado funciona.

Y aquí los coding agents tienen un papel fundamental.

Pueden ayudarnos a interpretar documentación, explorar alternativas, construir componentes, ejecutar comandos y depurar errores.

Pero hay algo que no debemos perder de vista:

Generar código no significa necesariamente haber construido algo que funciona.

Por eso la ejecución y la validación son fundamentales.

En Z2H queremos que el estudiante desarrolle la capacidad de trabajar con sistemas reales, utilizando agentes como parte de su proceso de ingeniería.

**No se trata solamente de aprender tecnologías. Se trata de aprender a construir con ellas.**
