# Intro — Bienvenida

Hola que tal...Bienvenidos a Z2H Academy.

En este video quiero mostrarles qué es Tutor, por qué lo estamos construyendo y, sobre todo, qué problema intenta resolver.

Pero antes de hablar de Tutor, quiero darte mas conexto:

**la forma en que hoy se construye software está cambiando.**

Durante años aprendimos programación de una manera muy específica.

Clases.

Videos.

Tutoriales.

Documentación.

Notebooks.

Ejercicios.

Y después, cuando llegábamos a una empresa, descubríamos que el trabajo real era muy diferente.

Hoy estamos entrando en otra etapa.

En las empresas ya es cada vez más común trabajar con **coding agents**.

Herramientas como **Codex, Claude Code, OpenCode** y otros agentes pueden leer un proyecto, entender su contexto, modificar archivos, ejecutar comandos, investigar problemas, escribir código, ejecutar pruebas y participar directamente en el proceso de desarrollo.

Esto cambia algo fundamental.

El desarrollador ya no trabaja únicamente escribiendo código línea por línea.

Ahora trabaja junto a agentes capaces de construir.

Y esto nos lleva a una pregunta:

**Si esta es la forma en que cada vez más profesionales están construyendo software, ¿por qué deberíamos seguir aprendiendo como si estos agentes no existieran?**

En Z2H Academy decidimos aprovechar precisamente este cambio.

No queremos simplemente enseñar a utilizar IA.

Queremos construir una experiencia de aprendizaje que utilice **los mismos tipos de herramientas y dinámicas que los profesionales están empezando a utilizar en su trabajo diario.**

Porque aprender de la misma manera en que se trabaja tiene un poder enorme.

El estudiante no solamente aprende una tecnología.

Aprende a trabajar con ella.

Aprende a leer documentación.

Aprende a investigar.

Aprende a construir.

Aprende a ejecutar.

Aprende a validar.

Aprende a resolver problemas utilizando agentes como parte de su proceso de desarrollo.

Y aquí aparece Tutor.

Tutor es el **Agentic Learning Runtime de Z2H Academy**.

Su propósito es conectar estos coding agents con un sistema de aprendizaje estructurado:

**Roadmaps.**

**Developer Docs.**

**Labs.**

**Projects.**

**Validation.**

Y entornos reales donde todo esto puede ejecutarse.

La idea no es crear otro chatbot al que simplemente le hacemos preguntas.

La idea es mucho más interesante:

**hacer que un coding agent pueda operar dentro de un sistema de aprendizaje diseñado para construir conocimiento mientras se construye software.**

Porque si el futuro del desarrollo es cada vez más agéntico,

entonces el aprendizaje también debería empezar a serlo.

Y eso es exactamente lo que estamos construyendo en Z2H Academy.

En este video vamos a ver qué es Tutor, cómo funciona, qué papel tienen los coding agents y cómo estamos conectando todo esto para crear una experiencia de aprendizaje diferente.

Una experiencia mucho más cercana a la realidad de la industria.

**Aprender como se trabaja.**

Empecemos.


## Slide 01 — Apertura: Tutor conecta agentes con aprendizaje real

Z2H Academy parte de una idea diferente: aprender construyendo con coding agents.

El estudiante trabaja con inteligencia artificial, escribe y modifica código, ejecuta sistemas reales y valida resultados.

Pero un agente por sí solo no es un sistema de aprendizaje.

Necesita contexto. Necesita una estructura. Necesita saber dónde está el estudiante, qué está aprendiendo, qué debe construir y cómo comprobar si lo que hizo realmente funciona.

Ahí aparece Tutor.

Tutor no es un chatbot. No es el coding agent. Y tampoco es la fuente de verdad.

Tutor es el runtime que conecta al agente con el sistema de aprendizaje de Z2H.

## Slide 02 — La idea: del chatbot al entorno de aprendizaje

El modelo tradicional es bastante simple.

Una persona hace una pregunta, un chatbot responde, se copia algún código y después hay que descubrir qué hacer con él.

Z2H propone algo diferente.

Aquí existe un sistema de aprendizaje estructurado: Roadmaps, Levels, Sections, Developer Docs, Projects y Labs.

Tutor conecta ese sistema con los coding agents.

Y finalmente existe el entorno donde todo ocurre: la máquina del estudiante, Docker, una máquina virtual, Codespaces o incluso infraestructura con GPU.

Cada pieza tiene una responsabilidad.

El agente aporta la inteligencia.

Z2H aporta el conocimiento y la estructura.

El entorno aporta el cómputo.

Y Tutor conecta todo dentro de un mismo proceso de aprendizaje.

## Slide 03 — Qué es Tutor: un Agentic Learning Runtime

Entonces, ¿qué es realmente Tutor?

Tutor es un Agentic Learning Runtime.

Esto significa que proporciona al coding agent una interfaz estructurada para operar dentro de un proceso de aprendizaje.

En lugar de preguntarle al agente simplemente cómo aprender Data Engineering, el agente puede trabajar sobre un Roadmap concreto.

Puede conocer el Level actual.

Puede acceder a una Section.

Puede consultar la documentación correspondiente.

Puede trabajar sobre un Lab.

Puede ejecutar código.

Y puede validar el resultado.

La diferencia es importante.

El agente ya no está solamente respondiendo preguntas sobre una tecnología.

Está operando dentro de un sistema de aprendizaje.

## Slide 04 — Tutor no es el agente

Tutor tampoco pretende convertirse en otro coding agent.

Claude Code, Codex y OpenCode son los agentes.

Ellos razonan, generan código, modifican archivos, ejecutan comandos y resuelven problemas.

Tutor tiene otra responsabilidad.

Proporciona al agente el contexto y la interfaz necesaria para trabajar dentro de Z2H Academy.

Y esta separación es fundamental.

Porque el agente puede cambiar.

Hoy puede ser Claude Code.

Mañana puede ser Codex.

Después puede aparecer otro agente completamente diferente.

La arquitectura de Tutor no depende de cuál sea el agente.

El agente cambia.

Tutor permanece.

## Slide 06 — De chatbot a Learning Runtime

Aquí está uno de los cambios más importantes.

## Slide 10 — Por qué MCP

MCP es una pieza importante de esta arquitectura.

Funciona como la interfaz entre el coding agent y Tutor.

Gracias a esto, Z2H no necesita construir una integración completamente diferente para cada agente.

Los agentes pueden interactuar con el mismo runtime a través de una interfaz común.

Esto permite que Tutor evolucione independientemente del agente que esté utilizando el estudiante.

Y también permite que el ecosistema de Z2H pueda incorporar nuevos agentes sin tener que reconstruir todo el sistema.

MCP no es el producto.

Es el protocolo que permite conectar las piezas.

## Slide 12 — Ejecución local y remota

El aprendizaje tampoco tiene que depender de un único tipo de infraestructura.

El estudiante puede trabajar localmente utilizando Linux, Docker o una máquina virtual.

Pero también puede trabajar en un entorno remoto.

Por ejemplo, una máquina en la nube, GitHub Codespaces o una plataforma con GPU.

Esto es especialmente importante para disciplinas donde el cómputo puede ser costoso.

El sistema de aprendizaje no necesita saber dónde está físicamente la máquina.

Tutor separa el proceso de aprendizaje del lugar donde se ejecuta el cómputo.

El mismo Roadmap puede terminar ejecutándose en diferentes infraestructuras.
